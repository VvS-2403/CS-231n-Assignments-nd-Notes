## Object Detection

- Object detection is significantly harder than localization because the number of objects is unknown and variable.
- An image could have zero cats, or it could have twenty ducks.

- **Why regression fails:**
  - If we treat this as a pure regression problem, the network needs to output a vector of coordinates.
  - But how long should the vector be? If there are 3 objects, we need 12 outputs. If there are 10 objects, we need 40 outputs.
  - Neural networks require fixed-size output tensors, making naive regression impossible.

- **The Sliding Window Expense:**
  - Instead of regression, we could treat it as classification.
  - We extract small sub-regions (crops) of the image at various locations, scales, and aspect ratios.
  - We pass every single crop through a CNN and classify it as "Dog," "Cat," or "Background."
  - Because objects can be any size and located anywhere, we would need to evaluate millions of possible crops per image.
  - Passing millions of crops independently through a deep CNN is computationally intractable.

---

## Region Proposals / Selective Search

- To make object detection feasible, computer vision researchers historically relied on non-deep-learning heuristic algorithms called **Region Proposal** methods.
- The most famous of these is **Selective Search**.
- It looks at the image pixels and groups them based on low-level cues like color similarity, texture, and enclosed boundaries.
- It finds "blobby" regions that are likely to contain objects, regardless of what the object actually is.
- Instead of searching millions of windows, Selective Search can rapidly (in a few seconds on a CPU) generate roughly 2,000 region proposals per image.
- This drastically reduces the search space for the CNN, changing the problem from "search everywhere" to "evaluate these 2,000 specific blobs."

---

## R-CNN

- The **Regions with CNN features (R-CNN)** algorithm (Girshick et al., 2014) was the first major success connecting deep learning with object detection.

- The pipeline works as follows:
  1. **Proposals:** Run Selective Search on the input image to generate ~2,000 region proposals (Regions of Interest, or RoIs).
  2. **Warping:** Because the CNN requires fixed-size inputs (e.g., $224 \times 224$), every single proposed region is cropped from the image and aggressively warped/resized to the required dimensions, regardless of its original aspect ratio.
  3. **Feature Extraction:** Forward *each* of the 2,000 warped regions through a pre-trained CNN independently to extract a feature vector (e.g., 4096-dimensional).
  4. **Classification:** Pass the feature vector into a set of linear Support Vector Machines (SVMs) to classify the object category (or background).
  5. **Bounding Box Regression:** Pass the feature vector into a linear regression model that predicts minor offsets to correct the bounding box shape.

- **The Nightmare of Training R-CNN:**
  - Training R-CNN was a complex, multi-stage pipeline.
  - You had to first fine-tune the CNN with log loss, then cache all features to disk (requiring hundreds of gigabytes).
  - Then train the SVMs with hinge loss, and finally train the bounding box regressors.
  - It was an ad-hoc system without end-to-end learning.
  - Furthermore, inference was incredibly slow.
  - Because each of the 2,000 regions passed through the CNN independently, processing a single image took roughly 47 seconds with a VGG16 backbone.

---

## Fast R-CNN

- To solve the speed issues of R-CNN, **Fast R-CNN** introduced a brilliant architectural insight: **pass the WHOLE image through the CNN once.**
- Instead of cropping images and running the CNN 2,000 times, Fast R-CNN takes the high-resolution input image and runs it through the convolutional layers once to produce a single high-resolution feature map.
- The region proposals (still generated by Selective Search) are then projected directly onto this feature map.

### RoI Pooling: The Mechanical Details
- Because the proposals vary in size, the projected regions on the feature map also vary in size.
- However, the fully connected layers at the end of the network still demand a fixed-size input.
- This is solved by the **RoI Pooling** layer.
- For any given region proposal on the feature map, RoI Pooling divides it into a fixed grid (e.g., $7 \times 7$ cells).
- It then performs Max Pooling within each grid cell.
- No matter how large or small the original proposal was, snapping it to a $7 \times 7$ grid and pooling within the cells guarantees that the output feature tensor is exactly $7 \times 7 \times D$ (where $D$ is the depth of the feature map).
- These fixed-size features are then flattened and fed into fully connected layers that simultaneously predict the class (Softmax) and the bounding box offsets (Smooth L1 Loss).

- **Performance improvements:**
  - Fast R-CNN allowed for end-to-end training with a multi-task loss, eliminating the complex disk caching and SVM training of R-CNN.
  - Inference time plummeted from 47 seconds to roughly 0.32 seconds (excluding proposal generation).
  - However, a new bottleneck emerged: computing the Selective Search proposals on the CPU now took longer (~2 seconds) than the entire neural network evaluation.

## Faster R-CNN

- **Faster R-CNN** achieved true end-to-end object detection by asking a simple question: "If the CNN is already computing a rich, high-resolution feature map, why don't we use that feature map to predict the region proposals themselves?"
- Faster R-CNN completely removes the slow Selective Search algorithm and replaces it with a **Region Proposal Network (RPN)** inserted directly into the architecture.

### Anchor Boxes and the RPN
- The RPN slides a small network over the convolutional feature map.
- At every spatial position, it considers $k$ reference boxes of various scales and aspect ratios, called **Anchor Boxes**.
- For every anchor box at every position, the RPN predicts two things:
  1. An "objectness" score (is there an object here, or is it background?).
  2. Bounding box regressions (offsets to shift and scale the anchor box to better fit the object).
- The proposals with the highest objectness scores are then passed into the standard RoI Pooling layer, exactly as in Fast R-CNN.

- **The 4 Losses:**
  - Faster R-CNN is a complex beast jointly trained on four separate losses:
    1. **RPN Classification:** Log loss for object/background prediction.
    2. **RPN Regression:** Smooth L1 loss for anchor box coordinate offsets.
    3. **Final Classification:** Softmax loss for the final object categories.
    4. **Final Regression:** Smooth L1 loss for the final bounding box refinements.

- By making the CNN do the proposal work, Faster R-CNN dropped inference time to roughly 0.2 seconds per image, achieving real-time or near-real-time performance with high accuracy.

## RoI Pool vs RoI Align

- In both Fast and Faster R-CNN, the RoI Pooling operation suffers from a subtle flaw: **quantization (rounding)**.
- When mapping a bounding box from the original image to the downsampled feature map, the coordinates rarely fall exactly on integer indices.
  - For example, dividing an image coordinate by 16 might yield 4.7. RoI Pooling simply rounds this to 4.
- Furthermore, when dividing the region into a $7 \times 7$ grid, if the region's width is 10, $10 / 7 = 1.42$. RoI pooling forces the grid cells to have integer sizes by rounding again.
- This double quantization causes the pooled features to be misaligned with the original image pixels, sometimes by several pixels.
- For object detection (drawing bounding boxes), this small error is acceptable.
- But for pixel-perfect Instance Segmentation, it is disastrous.

- **RoI Align**, introduced in Mask R-CNN, fixes this.
- Instead of rounding, RoI Align allows floating-point coordinates for the grid cells.
- To determine the feature value at these fractional locations, it uses **bilinear interpolation**—looking at the four nearest neighboring integer cells in the feature map and computing a weighted average based on distance.
- This entirely removes quantization errors, ensuring exact spatial alignment.

## Mask R-CNN

- **Mask R-CNN** extends the Faster R-CNN architecture to perform **Instance Segmentation**.
- It does this by taking the exact Faster R-CNN pipeline (with RoI Align replacing RoI Pool) and adding a third parallel branch alongside the classification and bounding box regression branches.
- For every region of interest, this new branch outputs a binary segmentation mask.
- If there are $C$ possible classes, the network outputs $C$ separate masks of size $14 \times 14$ (a tensor of $C \times 14 \times 14$).
- The classification branch decides which class the object belongs to, and we simply select the corresponding mask from the $C$ options.
- The $14 \times 14$ mask is then scaled up to the size of the bounding box to segment the object in the final image.

- Remarkably, this flexible architecture can be easily extended to other tasks.
- By changing the target of the mask branch, Mask R-CNN can perform **Pose Estimation**, predicting the precise locations of keypoints (like elbows, knees, and shoulders) on human figures.

## YOLO / SSD (Single-Stage Detectors)

- While Faster R-CNN is highly accurate, it is a two-stage detector (Stage 1: RPN proposals, Stage 2: RoI Pooling and final classification).
- This two-stage process inherently limits its speed.
- Algorithms like **YOLO (You Only Look Once)** and **SSD (Single Shot MultiBox Detector)** discard the region proposal paradigm entirely in favor of a single-stage, grid-based approach.

- The entire image is passed through a CNN to produce a grid (e.g., $7 \times 7$).
- We imagine a set of $B$ **base boxes** (anchors) centered at every single grid cell.
- Instead of pooling features, the network directly predicts everything from the grid cell's feature vector.
- For every single base box in every grid cell, the network regresses 5 values: $(dx, dy, dw, dh, \text{confidence})$, representing the spatial offsets from the anchor box and the confidence that an object exists.
- Simultaneously, the cell predicts the probability scores for each of the $C$ object classes.
- Therefore, the final output tensor is of size:
  $$ 7 \times 7 \times (5B + C) $$

- **Tradeoff:**
  - Single-stage detectors are incredibly fast (capable of running well over 60 frames per second), making them ideal for robotics and autonomous driving.
  - However, they historically struggle to achieve the same level of accuracy as two-stage detectors like Faster R-CNN, particularly for very small objects.

## 3D Object Detection

- As autonomous vehicles and robotics advanced, detecting objects in 2D images became insufficient.
- We need to know where objects are in 3D physical space.
- The goal is to predict 3D oriented bounding boxes parameterized by 9 variables: $(x, y, z, w, h, l, \text{roll}, \text{pitch}, \text{yaw})$.

- **Monocular Camera Challenges:**
  - Predicting 3D boxes from a single 2D image is notoriously difficult due to scale and distance ambiguity.
  - A 2D bounding box on the camera's image plane corresponds to a 3D **frustum** (a truncated pyramid) projecting out into the world.
  - The object could exist anywhere along that viewing ray.

- **Camera + LiDAR Fusion:**
  - To solve depth ambiguity, systems fuse camera imagery with LiDAR point clouds.
  - Multi-view networks can take LiDAR bird's-eye views, LiDAR front views, and RGB images, processing them together to accurately regress 3D boxes.

- **RGB-D Voxelization:**
  - With depth cameras (RGB-D), the 3D point cloud can be partitioned into a regular 3D grid called voxels.
  - Each voxel cell contains the aggregated RGB features of the points within it.
  - We can then apply a "Faster R-CNN in 3D" approach, using 3D Region Proposal Networks and 3D Convolutional layers on the voxelized data to predict 3D bounding boxes.

## Dense Captioning, VisualGenome, Scene Graphs

- Beyond drawing boxes and segmenting pixels, higher-level understanding requires language and relationship mapping.

- **Dense Captioning:**
  - This task merges Object Detection with Image Captioning.
  - Instead of labeling a bounding box as "person," a dense captioning model uses an RNN language model to generate a rich description, such as "man in a blue shirt sitting at a wooden table."

- **VisualGenome:**
  - To train such models, researchers created VisualGenome, a massive dataset with over 108k images and 5.4 million dense region descriptions.
  - It heavily maps attributes and relationships to WordNet synsets.

- **Scene Graphs:**
  - Taking this a step further, scene graph generation aims to extract not just the objects, but a directed graph of their relationships.
  - For instance, detecting a "man" and a "horse," and predicting the relationship edge "riding," resulting in a structured understanding: (Man $\rightarrow$ riding $\rightarrow$ Horse).

## Summary & Key Takeaways

- **Semantic Segmentation** advanced from terribly inefficient sliding windows to Fully Convolutional Networks utilizing encoder-decoder architectures with downsampling and **Transposed Convolutions** for upsampling.
- **Classification + Localization** treats bounding box prediction as a multitask learning problem using regression alongside standard classification.
- **Object Detection** evolved dramatically: from the slow, heuristic-driven **R-CNN**, to the feature-sharing **Fast R-CNN**, to the fully deep-learning, anchor-box-driven **Faster R-CNN**.
- **Instance Segmentation** was achieved via **Mask R-CNN** by adding a parallel mask prediction branch and solving quantization errors with **RoI Align**.
- **YOLO and SSD** traded some accuracy for incredible speed by skipping region proposals and predicting boxes directly from a spatial grid.
- Modern vision extends these 2D concepts into **3D Object Detection** using voxelization and sensor fusion, and into high-level semantic understanding via **Scene Graphs** and **Dense Captioning**.
